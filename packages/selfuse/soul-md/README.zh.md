# @dsh-selfuse/soul-md

[English](README.md) | 中文

## 概述

本插件读取本地 Markdown 人设卡并注册 `soul:persona` 系统提示词段。它可监听文件，并为之后的提示词组装更新该段。人设卡对进程内 Agent 全局生效，因此应把内容视为指令，而不是不受信的参考资料。

## 配置

`path` 可用绝对文件路径或相对 DSH 用户目录的路径。文件不可读时使用 `fallback`；空回退文本不注册段落。`order` 默认为 0，`watch` 默认为 true，`debounceMs` 控制重载延迟。高级选项 `complete` 会使人设卡成为完整系统提示词，可能移除其他段落。

## 提示词行为

插件使用与部署人设不同的段落名。`{{model}}`、`{{cwd}}` 等变量在渲染时解析。启用监听后，保存人设卡会为后续组装重新注册段落；已发送的请求不会被改写。

## 模型体验

### 人设卡段落

#### 模型看到什么

文件或回退文本有内容时，模型把渲染后的人设卡作为 `soul:persona` 系统提示词段看到。该段对进程作用域内所有 Agent 生效，包括子代理。

#### Token 影响

每次组装请求时，完整渲染的人设卡都会增加系统提示词 token。过长的人设卡会明显增加成本并挤占其他上下文。

#### KV Cache 影响

未变化的卡片保持稳定前缀。保存修改会改变后续组装的段落，并可能使供应商可复用的前缀失效；此前请求不变。

## 已知限制与待办

- 卡片中的字面 `{{` 与 `}}` 会和提示词变量语法冲突；未知变量可能导致渲染失败。
- `complete: true` 可能抑制其他系统提示词段，仅应在审阅完整组成后使用。
- 旧版上游 README 的版本声明含 NUL 字节；这里删除了受损声明，没有重复它。

### 开发备注

维护中的宿主入口是 `index.js`，浏览器入口是 `client.js`。DSH 升级后应重新检查提示词组成和文件监听行为。
