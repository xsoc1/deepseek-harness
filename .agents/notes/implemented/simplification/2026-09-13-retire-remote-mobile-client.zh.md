# Agent Note: 退役远程移动端客户端

Status: implemented

[English](2026-09-13-retire-remote-mobile-client.md) | 中文

## Problem

自用部署没有独立 `/m/` 客户端的用户。保留它需要第二套应用 bundle、独立 RPC 与 SSE 传输、PWA 缓存、移动端专用设置、重复的对话渲染以及第二条验证路径。这些维护成本不能改善实际使用的完整远程桌面工作流。

## Decision

`@dsh-selfuse/remote-web-ui` 只提供一种远程界面：完整 dsh Web UI。配对签发返回 `/?pair=...`，接受成功后重新载入同一个 Web 应用；启用远程桌面通道时，已配对浏览器使用现有远程桌面通道。

Host 不注册 `/m`、`/m/`、`/m/api/*`、移动端静态路由或移动端 RPC 传输。构建不生成或发布移动端 bundle 与 PWA 资产。设置 schema 与设置卡片不提供移动端专用输入框选项。

桌面配对面板只展示一个二维码和一个远程设备链接。设备 Cookie、在线心跳、撤销、局域网地址、Tailscale Serve 和 Cloudflare 隧道支持仍属于桌面工作流。

## Alternatives considered

**禁用 `/m/` 但保留源码。** 这可以减少运行时暴露，却会保留最大的维护与测试成本。当前没有用户需要一套休眠的第二应用。

**把 `/m/` 重定向到桌面 UI。** 这种做法会在没有兼容需求时保留旧入口，还可能掩盖陈旧收藏链接。返回正常的不存在响应可以明确表示该界面已经退役。

**同时修复两种界面。** 移动端传输可以增强韧性，但仍会留下两套对话客户端和两套同步实现。此部署只使用完整 Web UI。

## Consequences

远程电脑只有一条配对与渲染路径，本包也只有一套浏览器构建。`/m` 链接、已安装移动端 PWA 和移动端专用设置停止工作。小屏幕使用完整 Web UI，不再获得专用布局。重新引入该客户端时必须存在当前用户、单独论证的权限集合，以及移动端网络和会话同步的端到端负责人。

路由回归测试固定根路径配对链接；运行时验证固定退役 HTTP 路径不存在，并通过已配置的远程主机名验证完整桌面端启动。
