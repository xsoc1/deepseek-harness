# Agent Note: 自用控制台中的只读远程与更新检查

Status: implemented

[English](2026-09-16-control-gui-read-only-checks.md) | 中文

## Problem

控制台原本显示本机 Web 与 Tailscale 状态，却不能指出 Serve 的 HTTPS 根路径是否真正转发到 DSH。移除旧更新器后，也没有安全入口查看活跃 WSL 工作树是否已包含当前上游提交。本机状态变绿容易被误读为 iPad 会话正常，Windows 镜像版本也容易被误读为运行版本。

## Decision

两个按需按钮通过现有后台轮询进程执行只读命令，并在日志区返回有时间上限的报告。远程体检分别检查本机 HTTP、Windows Tailscale 服务和后端、Serve 的 HTTPS 根路径代理目标及 Funnel 暴露情况，以及本机不经代理的 HTTPS 请求。它只报告关键词数量而不展示 Web 日志正文，并明确不验证移动端浏览器状态。更新预检解析稳定的 WSL 源码链接，报告分支、版本、HEAD、未提交项数量，以及是否存在指向同一 HEAD 的备份分支。它不执行 fetch，仅查询 `origin` HEAD；只有提交已经存在于本地时才判断祖先关系。两项检查都不修改 DSH、Serve、Git 引用或用户配置。

## Alternatives considered

**恢复一键更新或 Serve 修复。** 自动变更需要独立且经过审查的升级或网络修复流程；从日常控制台点击可能丢失本地工作或改变远程暴露范围。

**把本机 HTTPS 探测成功视为移动端会话正常。** 电脑上的探测不使用 iPad 浏览器状态、配对数据或会话流，因此无法证明移动端已加载或同步。

**预检时获取上游对象。** Fetch 会改变远端跟踪引用，模糊预览与升级准备的界限。报告会明确说明何时必须在另行审查后获取提交，才能计算准确的源码差异。

## Consequences

两个检查在不恢复旧变更路径的情况下给出可操作的本机分层报告。有时限的网络查询会短暂延后后台状态轮询；超时会显示为明确的未知结果。Serve 路由样例、临时 Git 远端和隔离的轮询命令测试固定只读行为。报告不会声称远程设备会话正常。
